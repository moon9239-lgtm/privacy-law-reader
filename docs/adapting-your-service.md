# 내 서비스에 맞게 바꾸기

이 리더는 개인정보 보호법을 예시로 담고 있지만, 같은 구조로 다른 공개 문서 리더를 만들 수 있습니다.

## 1. 다른 분야의 데이터로 바꾸기

1. 먼저 다루려는 분야를 하나로 좁힙니다. 예를 들어 조례, 고시, 내부 공개 매뉴얼, 제품 약관처럼 공식 원문이 있는 자료가 좋습니다.
2. `src/law-data.js`처럼 화면이 읽는 데이터 파일을 찾습니다.
3. 기존 개인정보 보호법 조문을 새 분야의 항목으로 바꿉니다.
4. 항목마다 제목, 본문, 관련 문서 링크, 출처 확인일을 함께 남깁니다.
5. 화면 문구에서 개인정보 보호법에만 맞는 표현을 새 분야에 맞게 고칩니다.

## 2. MCP 또는 API로 최신 여부 확인하기

1. 공식 원문을 제공하는 MCP, 공식 API, 검색 페이지가 있는지 확인합니다.
2. 자동 도구가 있더라도 결과를 그대로 믿지 말고 공식 페이지를 다시 엽니다.
3. 바뀐 항목, 확인한 공식 URL, 확인한 날짜를 기록합니다.
4. 데이터 파일을 수정한 뒤 `npm.cmd test`와 `npm.cmd run build`를 실행합니다.

MCP나 API는 갱신 작업을 돕는 도구입니다. 일반 방문자가 리더를 열 때 꼭 필요한 기능으로 만들지 않는 편이 공개 배포와 유지보수에 단순합니다.

## 3. 공식 PDF는 묶지 말고 링크하기

1. 공식 기관이 제공하는 PDF나 첨부문서 URL을 찾습니다.
2. PDF 파일 자체를 저장소에 넣지 않습니다.
3. 데이터에는 문서 제목, 설명, 공식 URL만 적습니다.
4. 링크가 깨졌는지 정기적으로 확인합니다.

이렇게 하면 저작권, 용량, 최신성 문제를 줄이고 사용자가 공식 원본으로 바로 이동할 수 있습니다.

## 4. 분석 기능은 비공개 확장으로 분리하기

1. 공개 리더에는 추적 코드와 개인 분석 엔드포인트를 넣지 않습니다.
2. 방문 통계가 필요하면 별도 비공개 저장소나 별도 배포 프로젝트에서 확장합니다.
3. 공개 저장소에는 분석 서비스 토큰, 프로젝트 ID, 수집 URL을 커밋하지 않습니다.
4. 분석 확장을 붙인 배포본과 순수 공개 리더 배포본을 구분합니다.

처음에는 정적 리더만 유지하는 편이 가장 안전합니다. 데이터가 안정된 뒤 필요한 기능을 하나씩 분리해서 더하세요.
